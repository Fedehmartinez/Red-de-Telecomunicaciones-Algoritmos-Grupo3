Parte 1.2

Orden temporal del algoritmo de Floyd

El algoritmo de Floyd calcula las distancias mínimas entre todos los pares de vértices. 
Para cada vértice intermedio, comprueba si pasar por él permite encontrar un camino más económico.
Su orden temporal es (O(V^3)), porque utiliza tres ciclos que recorren los vértices: uno para el vértice intermedio, 
otro para el origen y otro para el destino.
En este caso hay 4 ciudades, por lo que se realizan (4^3=64) combinaciones de índices en los ciclos principales.
En general, no se puede reducir el orden del algoritmo clásico de Floyd, aunque sí se pueden realizar mejoras prácticas, 
como evitar cálculos innecesarios cuando no hay caminos posibles o utilizar algoritmos alternativos si solo se necesitan algunas distancias.
En este escenario, el costo es muy bajo porque hay pocas ciudades. Sin embargo, si la aerolínea incorporara muchas más ciudades, 
el tiempo de ejecución crecería considerablemente, ya que el costo aumenta de forma cúbica.

Para determinar la ubicación más conveniente, se suman las distancias mínimas desde las otras ciudades hasta cada posible ubicación del 
taller, respetando el sentido de los vuelos.

Montevideo: 300 + 400 + 810 = 1510.
Colonia: 760 + 200 + 610 = 1570.
Buenos Aires: 560 + 800 + 410 = 1770.
Punta del Este: 150 + 390 + 550 = 1090.

Por tanto, la ciudad más conveniente para instalar el taller de mantenimiento es Punta del Este, ya que presenta el menor costo total de 
traslado desde las otras tres ciudades, con 1090 unidades de distancia.

Lista<V> recuperarCamino(int origen, int destino) {
    Lista<V> camino ← lista vacía
    int actual ← destino

    si distancia[origen][destino] = ∞ entonces
        retornar camino
    fin si

    mientras actual ≠ origen hacer
        insertar actual al principio de camino
        actual ← predecesor[origen][actual]

        si actual = null entonces
            retornar lista vacía
        fin si
    fin mientras

    insertar origen al principio de camino
    retornar camino
}
